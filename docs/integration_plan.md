# Integration Plan

## 总体目标

让共享新闻/事件底座成为 `Investment` 里所有新闻相关能力的共同上游。

## 下游一：行业雷达

### 当前状态

- 已经每日运行
- 已经抓取部分新闻源
- 已有行业映射和 `policy_articles` 逻辑

### 未来角色

- 成为 `baseline news collectors` 的主要运行位
- 不再只为自己服务
- 把抓到的新闻先写入共享库，再从共享库消费行业视图

### 需要调整的地方

- 把“直接抓新闻 -> 直接做 overlay”改成：
  - 抓取
  - 标准化入共享库
  - 从共享库读取行业映射结果

## 下游二：投资机会日报 / 周报

### 当前状态

- 自己抓新闻
- 自己做 signals
- 自己生成 digest

### 未来角色

- 只消费共享库
- 不再单独维护独立新闻抓取链

### 需要调整的地方

- 把当前 `refresh_market_news.py` 的职责拆开
- 日报更多负责：
  - 选择视图
  - 解释与呈现
  - 与 tracker / watchlist / portfolio 结合

## 下游三：研究工作流

### 当前状态

- 研究过程中可能会做定向抓取
- 但结果容易留在局部脚本、笔记或工作区里

### 未来角色

- 研究线程也作为共享库的生产者
- 但其写入 scope 要明确标记为 `targeted_research`

### 需要调整的地方

- 增加“定向抓取 -> 回写共享库”的标准入口
- 把公司、行业、主题关联信息写回

## 推荐推进顺序

### Phase 1

- 固化产品定义
- 固化对象模型
- 固化 ranking v1

### Phase 2

- 设计共享库 schema
- 设计 source registry
- 定义 baseline / targeted collector 契约

### Phase 3

- 先接行业雷达的公共新闻源
- 在 `private runtime` 跑出第一版共享库

### Phase 4

- 让日报改为只消费共享库
- 关闭日报内部重复抓取链

### Phase 5

- 研究工作流接入定向回写
- 完成多消费者统一闭环

## 当前结论

这不是一个“日报优化小改动”，而是一次上游基础设施重构。

但因为两边已经各自积累了部分成熟能力，所以这次重构不需要推倒重来，应该走：

- 继承机会报告的 source catalog 与 article/signal 入库经验
- 继承行业雷达的 private runtime 运行位、标准化与映射经验
- 在新共享库上重新汇合
