# Unified News System Phase 1 Plan

## 文档目的

这是一份 `动态更新` 的阶段规划书，用来约束 `News Event Hub` 当前阶段的真实目标，避免后续讨论和实现再次发散。

本文件不是一次性说明文档，而是一个长期维护的 `source-of-truth`：

- 每完成一项，就把对应 checklist 打勾
- 每当阶段边界发生变化，就优先更新这份文档
- 后续实施、部署、接口迁移，都以这里为准

## 当前阶段目标

当前阶段的目标不是继续扩一个“更复杂的新闻产品概念”，而是先把 `Investment` 工作区里已经存在的新闻能力统一起来，形成一个可共享、可部署、可迁移的 `统一新闻系统`。

阶段目标包括两件事：

1. 把现有新闻源、新闻抓取链路、新闻结构抽象并整合为一个统一整体
2. 把统一后的系统部署到 `private runtime`，并为旧接口和旧消费者准备迁移与告知路径

## 这个阶段不做什么

为了控制范围，本阶段明确 `不做` 以下内容：

- 不把 `OpenBB`、价格、指数、proxy、context、flow 等数据型输入并入新闻系统
- 不把行业雷达的上下文增强层混成新闻库的一部分
- 不先做完整的 ranking 重设计
- 不先追求全量新源扩张
- 不先做复杂的事件聚类、机会评分、研究动作编排

这些都可以是后续阶段，但不是本阶段的完成标准。

## 当前边界

### 边界一：系统只处理 News

统一新闻系统当前只负责 `News`，不负责非新闻型上下文数据。

不纳入本系统主体的内容包括：

- OpenBB sidecar 数据
- 商品与宏观价格序列
- 航运景气指数
- 运价、库存、开工率、资金流
- 基本面代理变量
- 雷达内部的 context / proxy / flow / tape 层

### 边界二：News 只分两条 lane

统一新闻系统当前只保留两类新闻：

#### 1. `confirmation lane`

作用：

- 确认事实
- 提供明确时间点
- 提供高可信事件输入

典型来源：

- 公告
- 交易所
- 监管
- 政府与部委
- 财联社
- 金十
- Reuters
- Bloomberg
- 其他主流财经确认源

#### 2. `signal lane`

作用：

- 提前暴露研究线索
- 反映讨论发酵
- 暴露尚未完全证实但值得优先验证的变化

典型来源：

- X / Twitter
- Reddit
- Polymarket
- 微博
- 雪球
- 股吧
- 小红书等高增量社区源

## 统一系统要服务谁

统一新闻系统不是单一下游产品的私有库，而是整个 `Investment` 工作区的共享底座。

当前明确服务三类消费者：

- `industry_signal_radar`
- `投资机会发现 / 日报 / 周报`
- `研究线程 / 对象研究工作区`

目标是：

- 不再让这些消费者各自维护一套新闻库
- 让行业雷达与投资机会发现共享同一套新闻事实层
- 让研究线程的定向新闻能力未来也能回写共享层

## 当前已知的源资产

### 1. 投资机会报告链路

当前已存在一套较宽的新闻源 catalog，覆盖：

- 公告 / 监管 / 政府
- 财经快讯 / 媒体
- 社交 / 讨论区 / 传闻层

这条链路是当前最宽的新闻源资产池，但还没有被抽象成共享新闻系统的统一 source map。

### 2. 行业雷达链路

当前已存在一套偏 `公告 / 政策 / 快讯` 的新闻层能力。

但行业雷达内部还混有大量 `proxy / context / data sidecar`，这些不能直接并入统一新闻系统主体。

### 3. News Event Hub 当前定义层

当前子工作区已经承载：

- 产品定义
- 架构定义
- source registry 草案
- schema 草案

但它还没有完成对现有两条旧链路的正式吸收和统一。

## Phase 1 的真实交付物

如果这一阶段做对了，应该交付以下结果：

1. 一份统一的新闻系统边界定义
2. 一份统一的 source inventory 与 lane 归属表
3. 一套统一的新闻库 schema 或最小可行数据模型
4. 一个运行在 `private runtime` 的共享新闻数据库
5. 一套对旧接口的兼容 / 替代 / 迁移说明
6. 一份给下游消费者使用的迁移告知文档

## 当前阶段的工作流

### Workstream A: 统一定义

把现有散落在多个系统里的新闻概念，统一成一个清晰边界：

- 什么算 News
- 什么不算 News
- 哪些源属于 confirmation lane
- 哪些源属于 signal lane

### Workstream B: 统一盘点

把当前三处资产盘成一个统一 source inventory：

- 投资机会报告
- 行业雷达
- News Event Hub

盘点结果必须能回答：

- 已接了哪些源
- 哪些只是候选
- 哪些应进入统一新闻系统
- 哪些应排除在新闻系统主体之外

### Workstream C: 统一落库

把确认进入本阶段的新闻源，统一写入 `private runtime` 上的共享数据库。

### Workstream D: 兼容旧接口

统一系统形成后，需要识别旧世界的入口和调用方：

- 哪些脚本还依赖旧新闻库
- 哪些接口需要兼容
- 哪些字段需要映射
- 哪些旧接口可以逐步废弃

### Workstream E: 迁移告知

对相关消费者给出明确迁移口径，而不是默默改底层。

当前相关方主要包括：

- `industry_signal_radar`
- `投资机会报告`
- 后续研究线程接入方

## 本阶段完成标准

以下条件同时满足，才算本阶段真正完成：

1. 已有新闻能力完成统一抽象，不再是多套并行的定义
2. 共享新闻数据库已在 `private runtime` 上可运行
3. 第一批实际源已写入共享新闻库
4. 行业雷达与投资机会发现至少知道如何消费这套共享库
5. 旧接口的兼容 / 替代 / 下线路径已经被写清楚

## 当前备注

当前阶段的重点不是“做出最强新闻系统”，而是先把已经存在的新闻资产收束成一个共同上游。

先统一，后扩展。
先共享，后优化。
先迁移清楚，后谈更复杂的 ranking 和事件层。
