# Acceptance Criteria

## 目标

这份文档回答一个问题：

什么状态下，`News Event Hub` 才算真正开始可用，而不是只是多了一个新目录。

## Phase 0: 定义完成

满足以下条件，才算完成定义阶段：

1. 已明确 source 分层
   - `confirmation lane`
   - `signal lane`
2. 已明确下游消费者
   - 行业雷达
   - 日报 / 周报
   - 研究工作流
3. 已明确 ranking 三层对象
   - article
   - event
   - opportunity
4. 已明确共享库与私有运行库边界

## Phase 1: 共享库可运行

满足以下条件，才算第一版共享库跑起来：

1. `private runtime` 上已有独立共享库
2. baseline collectors 能稳定写入
3. 同一篇文章不会因重复调度被无限重复入库
4. source health 能被记录
5. 至少能产出 article 层标准化对象
6. 固定抓取不是只停留在日更，而是已有可运行的高频 tick + 源级轮询间隔

## Phase 2: 事件层可用

满足以下条件，才算不再只是“新闻文章仓库”：

1. 多篇相关新闻能聚成同一事件
2. 事件有 `first_seen / last_seen / confirmation` 概念
3. 事件能映射到行业、公司或主题
4. 事件能区分“新增变化”与“旧闻复述”

## Phase 3: 下游真正接入

### 行业雷达

1. 新闻输入默认来自共享库，而不是私有抓取旁路
2. `policy_articles` 或等价视图由共享库文章 / 事件派生

### 日报 / 周报

1. 不再单独抓新闻
2. 重点新闻来源于共享库视图
3. 宏观主线不再被老旧背景材料占据
4. 公司新闻不再大量出现低投资价值噪音

### 研究工作流

1. 定向抓取可以回写共享库
2. 回写对象能保留 `targeted_research` scope

## 内容质量验收

这部分最重要。

### 宏观板块

合格标准：

- 能稳定给出真正新的宏观事件
- 不再大量出现历史背景说明
- 不再用纯价格播报充当主线

### 公司 / 行业板块

合格标准：

- 每条重点新闻都能映射到可研究对象
- 至少能解释“为什么值得现在看”
- 低价值交易、招商、泛公告噪音不会轻易挤进前排

### 舆论 / 赔率层

合格标准：

- 能作为早期信号进入系统
- 但不会未经确认直接压过事实层

## Ranking 验收

一个可接受的 ranking v1，至少应满足：

1. 重大新事件稳定靠前
2. 旧闻复述明显降权
3. 背景材料明显降权
4. 无对象映射的公司噪音明显降权
5. 舆论源被保留但不滥用

## 失败判据

出现以下情况，说明系统仍未达标：

- 日报头部仍常出现过期主线
- 宏观栏仍经常出现“缘由解释型”文章
- 公司新闻仍经常是无投资映射噪音
- 雷达和日报仍在各抓各的新闻
- 研究定向抓取仍只停留在局部工作区
