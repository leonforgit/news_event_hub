# Product Definition

## 一句话定义

`News Event Hub` 是 `Investment` 工作区里的共享新闻/事件输入层。

它的职责不是“再做一个新闻摘要器”，而是把分散在日报、行业雷达、研究线程里的新闻抓取与判断逻辑，沉淀成一套可复用的 `事实获取 -> 事件化 -> 映射 -> 排序 -> 多消费者分发` 基础设施。

## Why This Exists

当前 `Investment` 工作区里，至少存在三类彼此割裂的新闻使用方式：

- 日报链路自己抓新闻、自己做 signals、自己生成 digest
- 行业雷达自己抓新闻、自己做行业 overlay
- 研究线程偶尔会做定向抓取，但结果容易停留在局部工作区

这带来四个结构性问题：

- 重复抓取
- 重复解析
- 重复打标签
- 同一条新闻在不同链路里被做出不同判断

所以这个产品的目标不是单点提效，而是把“新闻相关能力”从下游产品里抽出来，变成一个统一上游。

## 北极星问题

这个系统最终要稳定回答的是：

- 今天发生了哪些新的、值得研究的事件
- 这些事件影响哪些公司、行业、主题或组合对象
- 哪些只是信息噪音，哪些值得进入后续研究或跟踪动作

## 用户与消费者

这个产品的直接“人类用户”并不是浏览器里的最终读者，而是 `Investment` 工作区内的多个消费系统与研究线程。

### 消费者一：行业雷达

行业雷达需要知道：

- 哪些行业今天出现了新的驱动
- 哪些政策、供需、价格、舆论开始形成共振
- 哪些行业值得打开进一步看

### 消费者二：日报 / 周报

日报和周报需要知道：

- 今天最值得解释和呈现的事件是什么
- 哪些旧主线应当被降权或移出
- 哪些事件值得进入 watchlist、tracker 或后续研究

### 消费者三：研究线程

研究线程需要知道：

- 某个对象发生了什么新事实
- 哪些新内容强化或削弱当前 thesis
- 定向抓到的内容如何回写共享系统，而不是只留在局部笔记

## 产品交付物

这个系统交付的不是“文章列表”，而是三层对象和若干消费视图。

### 1. Article

文章是最原始、最宽口径的信息承载体。

它回答：

- 哪个来源说了什么
- 发布时间大概是什么时候
- 这条内容是否可被后续结构化处理

文章层本身不是最终排序对象。

### 2. Event

事件是共享层的核心最小消费单位。

它回答：

- 真正发生了什么变化
- 这是新增信息还是旧闻复述
- 有多少来源确认
- 能映射到哪些公司、行业、主题或市场对象

下游消费者默认首先消费 `event`，而不是直接消费 `article`。

### 3. Opportunity

机会层不是“预测收益”，而是“是否值得进入投资研究动作”的排序对象。

它回答：

- 这个事件对当前研究与跟踪体系有多大意义
- 是否存在明确下一步动作
- 是否与 watchlist、持仓、主题链或行业雷达结果形成共振

## 事件最小定义

不是所有新闻都能升级成事件。

一个内容至少满足以下条件中的大部分，才应被视为可消费事件：

- 存在明确的新变化，而不是纯背景解释
- 时间点相对明确
- 主体相对明确
- 能映射到公司、行业、主题、宏观主线或市场对象
- 可以说明“为什么今天值得看”

以下内容默认不应作为高优先事件：

- 背景科普
- 历史缘由复盘
- 没有新增动作的纯价格播报
- 无研究映射关系的普通公司动态
- 单一脏源、且无法确认的噪音爆料

## 两条赛道

新闻系统必须从一开始就按两条赛道建模，而不是混成一个热度池。

### Confirmation Lane

`confirmation lane` 负责回答“发生了什么”。

典型来源包括：

- 公告
- 交易所
- 政府部委
- 央行
- 主流财经 API
- 稳定媒体

这条赛道更看重：

- 来源可信度
- 时间明确性
- 原始性
- 多源确认

### Signal Lane

`signal lane` 负责回答“市场开始如何讨论和定价”。

典型来源包括：

- X
- Reddit
- 股吧
- 论坛
- 社交平台
- Polymarket

这条赛道更看重：

- 异常度
- 热度变化
- 扩散速度
- 赔率或情绪变化
- 与事实层的偏离程度

`signal lane` 可以抬升优先级，但不应独立决定最终头部事件。

## 核心产品工作流

### 工作流一：公共采集

系统从多个稳定来源做公共采集，形成共享文章层。

### 工作流二：文章标准化

不同来源的内容被清洗为统一文章对象，为去重、聚类、映射和排序做准备。

### 工作流三：事件化

多条指向同一变化的文章被提升为事件。

这一步是整个产品最关键的价值创造环节，因为它决定系统是“新闻仓库”还是“事件底座”。

### 工作流四：对象映射

事件被映射到公司、行业、主题、宏观主线和其他研究对象。

### 工作流五：排序与分发

系统根据不同消费者需求，输出不同视图：

- 行业雷达视图
- 日报重点事件视图
- 对象研究视图
- 候选机会视图

### 工作流六：研究回写

研究线程中的定向抓取结果可以通过标准入口回写共享库，并明确标记来源 scope，而不是作为黑箱旁路存在。

## 消费契约

这个产品的一个重要原则是：下游消费者不应再自行维护独立新闻抓取口径。

### 行业雷达消费契约

行业雷达默认消费：

- 共享文章层
- 共享事件层
- 行业映射结果
- 适合做 overlay 的聚合视图

行业雷达不再把自己的私有抓取链路视为长期 canonical source。

### 日报 / 周报消费契约

日报和周报默认消费：

- 今日高优先事件列表
- 事件级解释字段
- 与 watchlist、tracker、portfolio 相关的排序结果

日报职责应逐渐收缩到：

- 视图选择
- 人类可读解释
- 呈现与发送

### 研究线程消费契约

研究线程默认消费：

- 某对象相关的新事实
- 某主题相关的新事件
- 某 thesis 的强化或冲突证据

研究线程同时也是生产者，允许把定向抓取结果回写共享层，但必须保留 `targeted_research` scope。

## 产品判断原则

### 原则一：排序对象必须升级

最终排序对象不能是文章，而必须是事件，必要时再上升到机会层。

### 原则二：系统优先发现变化，不优先复述背景

如果一条内容不能回答“今天新发生了什么”，就不该占据高优先级。

### 原则三：能映射到研究动作，比“像新闻”更重要

很多内容看起来像重大新闻，但如果无法映射到行业、公司、主题、组合对象或下一步研究动作，其投资价值就有限。

### 原则四：共享层优先，消费层尽量变薄

复杂性应尽量收敛在共享层，而不是在每个下游重复实现一遍。

### 原则五：研究工作流不是旁路，而是共享系统的一部分

研究过程中的定向抓取是高价值信息来源，应该成为共享库的增量输入，而不是长期停留在私人脚本中。

## V1 范围

### V1 必须完成

- 明确 source registry 基本口径
- 明确 `confirmation lane` 与 `signal lane`
- 明确 `article -> event -> opportunity` 三层对象
- 明确 baseline collectors 与 targeted collectors 的边界
- 明确行业雷达、日报、研究线程的消费契约
- 明确 v1 ranking 的硬规则与惩罚逻辑

### V1 可以暂缓

- 全部 collector 一次性接入
- 复杂机器学习排序
- 完整 UI 层
- 完整的人机交互产品界面
- 高度自动化的自学习优化闭环

## 明确不做的事

这个工作区不应被做成以下任何一种东西：

- 一个新的日报项目
- 一个新的行业雷达项目
- 一个临时抓新闻的脚本堆
- 一个直接提交原始新闻正文、缓存和主 SQLite 的仓库
- 一个把所有内容都做成摘要却不提供对象映射的“信息池”

## 成功长什么样

如果这个产品做对了，应该出现以下变化：

- 同一事件不再被日报、雷达、研究脚本各抓一遍
- 每条进入日报头部的内容都能解释“为什么今天值得看”
- 宏观主线不再被旧背景材料占据
- 公司新闻不再被无投资映射的噪音内容挤满
- 行业雷达与日报开始共享同一套事件事实层
- 研究线程抓到的新内容可以回流，变成全系统可消费资产

## 当前仍待决策的问题

产品方向已经相对明确，但以下仍是后续定义阶段需要继续敲定的问题：

- 共享库 schema 的第一版边界
- `event` 的第一版聚类策略与人工兜底机制
- `signal lane` 的 v1 纳入范围
- 映射层最小可行实体词表与对象注册表
- 哪些解释字段由共享层产出，哪些留给消费层生成

## 当前结论

`News Event Hub` 的本质不是“新闻抓取项目”，而是 `Investment` 工作区里的 `共享研究触发器基础设施`。

它的核心任务不是把文章收得更多，而是把真正值得研究的变化更早、更准、更一致地送到所有下游消费者面前。
